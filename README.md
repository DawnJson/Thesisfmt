# 论文格式体检 thesisfmt

把论文 `.docx` 拖进来，它按你学校或投稿期刊的格式规范逐条检查；能改的格式点一下就改好，改不了的告诉你在哪、该怎么改。Windows 桌面程序，完全离线。

![论文格式体检主界面：左侧是问题清单，右侧是论文预览](docs/screenshot.png)

## 为什么写这个

论文快交了，正文改了一遍又一遍，结果卡在格式上：页眉不对、目录页码对不上、图表编号没按章、参考文献悬挂缩进少了、前置部分该用罗马数字页码……学校的规范动辄几十页，格式检测一次打回来几十处，你只能对着规范一条条核、一处处改，改完再交，再被打回。

这些活大多是机械的：规范上写着「章标题三号黑体居中」，Word 文件里每一段实际是什么字体、什么字号，都读得出来。比对和改正交给程序，你的时间留给内容。

## 它做什么，不做什么

它会：

- 按规则包检查页面设置、页码、页眉、各级标题、正文、摘要与关键词、图表题注、三线表、脚注、参考文献编号等；
- 在内存里的副本上修复格式问题，每一步都能撤销；
- 把结果另存为修改后的副本，或带 Word 批注的副本；
- 本机装了 Word 或 WPS 时，借它们真正排版一遍，再查分页相关的问题。

它不会：

- 动你的原文件。所有修改都在副本上，保存时也是另存；
- 不经你同意改文字。「修复」只改格式，涉及文字的改动要你逐条看过、点了确认才写入；
- 联网。论文和设置都只留在你的电脑上；
- 替你过学校的格式检测。它是交稿前的自查，见[说在前面](#说在前面)。

## 下载安装

1. 打开 [Releases](../../releases/latest)，下载最新版本的安装包。两种任选其一：
   - `.msi`：Windows Installer 安装包；
   - `-setup.exe`：NSIS 安装程序。
2. 运行安装包。安装包没有数字签名，Windows SmartScreen 可能拦一下：点「更多信息」→「仍要运行」。
3. 支持 Windows 10 / 11（x64）。

## 用起来是什么样

### 打开论文

把 `.docx` 拖进窗口，或者点「选择文件」（打开文件后用工具栏的「打开」）。也可以在资源管理器里右键 `.docx`，「打开方式」选它。只支持 `.docx`；`.doc` 旧格式请先在 Word 里「文件 → 另存为 → Word 文档 (*.docx)」。

### 选规则包

顶栏「模板」决定按哪家的规范检查，第一次打开默认是清华大学硕士（`thu-master`）。在搜索框里输入学校、期刊或类别（比如「北京」）就能找到你的那一个。切换规则包只会重新检查，不会丢掉你已经做的修改。详见[模板库](#模板库)。

### 看问题清单

左边是问题清单，可以「按类别」或「按章节」分组，每条标着「错误」「警告」「提示」或「需人工确认」，写明「应为」什么、「实际」是什么，以及规范出处。点一条，右边的预览会跳到那一段；反过来在预览里点一段，清单也会定位到它的问题。

「需人工确认」是程序判断不了、需要你自己核对的事项，比如图是否精选、表达式是否转行得当。

### 修复格式

每条能自动修的问题旁边有「修复」，每组有「修复本组」，工具栏有「全部修复」。修复只改格式：字体、字号、行距、缩进、页边距、页码格式、三线表框线这类属性，不碰一个字。改坏了就点「撤销」，一步一步退回去。

程序会在修复前后比对正文和页眉页脚的全部文字，只要文字有变化就中止，不生成文件。

### 保存

- 「保存修改后的副本」：把当前修改另存为新文件，默认文件名是 `原名_修复.docx`；
- 「保存带批注副本」：把每个问题写成 Word 批注，方便你在 Word 里对照着改，默认 `原名_批注.docx`。

原文件始终不动。另外提醒一句：有的学校要求提交前删除全部批注，带批注副本只用来自查，别直接交上去。

### 需要改文字的问题

有些问题光改格式解决不了，得动文字：章序号「第一章」要写成「第1章」，附录编号不对，关键词分隔符不对，中文里混了半角标点或全角字母数字，英文摘要里混了中文标点，续表题注写得不对，标题里还留着模板的说明（「摘  要（三号黑体，居中）」）。

这些问题旁边是「改文字…」按钮。点开会列出改动：删掉的字标红加删除线，插入的字标绿，空格显示成 ␣。你看过没问题再点「确认修改」，不对就「取消」。每次确认都是独立的一步，同样能撤销。它们不会被「全部修复」或「修复本组」顺手改掉。

### 精确检查：借 Word / WPS 排一遍版

有些问题要真正分页之后才知道：表格跨页了没有、续表表头是否重复、图和图题是不是被分到两页、参考文献条目有没有跨页、目录里的页码和实际对不对得上、章节和摘要致谢有没有另起页、摘要和致谢有没有超出页数、页码是不是从该从的数字开始。

本机装了 Microsoft Word 或 WPS 文字时，打开文件后程序会自动做一次「精确检查」：在后台以只读方式打开你论文的一份临时副本，不显示窗口，让 Word / WPS 排版分页，再按规则包检查。一份 56 页的模板用 Word 实测十几秒，其中几秒是 Word 启动。

查出来的问题里，另起页、跨页表重复表头、图与图题同页、文献条目同页可以直接「修复」（只改段落或表格属性）。跨页表格可以点「拆为续表…」：在跨页处拆开表格，插入「续表」题注，把表头行复制到续表第一行，同样要你看过改动说明再确认。

修复或撤销之后分页可能变了，之前的结果随之作废，点「重新精确检查」即可。工具栏「精确检查」随时可以手动再跑一次。

## 模板库

规则包就是程序检查时依据的那份规范。顶栏「模板」打开模板库，列表按「我导入的 / 高校 / 期刊 / 其他」分组。

### 内置规则包

程序自带 115 个规则包，覆盖高校 83 所（109 个包）、期刊 6 种（6 个包）。同一所学校的研究生 / 本科、理工 / 文科等格式不同的，各有一个包，靠类别区分。

每个包都标了核对状态：

- 「已核对规范」（107 个）：包里每一条规则都对照过该单位的规范原文，或单位指定为规范的官方模板，出处写在规则旁边，检查结果里也能看到；
- 「未核对规范」（8 个）：只找到了官方模板或样例，没找到说明「以此为规范」的文件。规则依据模板里的格式和说明文字写成，参考价值低一些。

### 导入你自己的模板

学校不在列表里？如果你手里有学校发的 Word 模板，点「导入模板…」选 `.docx` 或 `.dotx`，程序会从模板的实际格式里提取规则包并切换过去，标「我导入的 · 未核对规范」。

能提取的有页面设置、页码格式、关键词分隔符、题注编号方式，以及各类段落（章标题、正文、摘要等）的字体、字号、加粗、对齐、行距、段前段后和缩进。页眉、精确检查、三线表、脚注、参考文献等不提取。每项取模板里的多数值，同类段落格式不统一就干脆不写那一项。

要注意的是，它照搬的是模板的格式。模板自己违反了规范，导入的包也会跟着错。模板里认不出章标题、正文、摘要这些段落时，导入会失败。

导入的规则包保存在 `%APPDATA%\io.github.thesisfmt\packs\`，文件名是 `user-<毫秒时间戳>.yaml`。

### 删除

只有导入的规则包能删：列表里那一行的垃圾桶按钮，删了不能撤销。删掉的正是当前在用的包时，程序换回默认规则包。内置规则包删不了。

## 设置

右上角的齿轮打开设置页。改动立即生效，保存在 `%APPDATA%\io.github.thesisfmt\settings.json`。

| 设置 | 默认 | 说明 |
|---|---|---|
| 工作副本 | 关 | 打开文件时在原文件同目录新建 `原名_工作副本.docx`，每次修复、撤销都自动写进去，不用再手动保存。同名文件已存在时自动编号，不会覆盖。下次打开文件时生效。后缀可改 |
| 修改后副本的文件名后缀 | `_修复` | 「保存修改后的副本」的默认文件名 |
| 批注副本的文件名后缀 | `_批注` | 「保存带批注副本」的默认文件名 |
| 默认规则包 | 默认（清华大学硕士，没有则列表第一个） | 启动时选用；还没打开文件时立即切换 |
| 精确检查使用 | 自动（优先 Word） | 本机同时装了 Word 和 WPS 时选用哪一个 |
| 打开文件后自动精确检查 | 开 | 关掉后可以随时手动点「精确检查」 |

## 隐私

**你的论文不会离开你的电脑。**

- 文件只在本机处理。检查和修复都是程序内置的 Rust 代码；精确检查调用的也是你本机已经装好的 Word / WPS。
- 程序不联网，没有统计，不上传任何内容。
- 想自己验证：断开网络，照常打开一篇论文检查、修复、保存，一切如常。看代码的话，`src-tauri/Cargo.toml` 里没有任何网络库，`src-tauri/tauri.conf.json` 的内容安全策略（`csp`）也只允许界面连接程序自身。

## 说在前面

这个程序能帮你省很多事，但有几件事得老实交代：

- **最终结论以学校为准。** 很多学校用格式检测系统（比如论无忧）出具检测合格证明，结果以学校指定的系统和老师的意见为准。这里的检查只是交稿前的预检，帮你先把能改的改掉。
- **规则只和规范原文一样好。** 规则包是对照规范原文一条条写的，规范没写清楚的地方，程序不替你猜：要么不查，要么列进「需人工确认」。规范本身有歧义、写成区间（如「段前 30～36 磅」）或者依赖人的判断时，结果需要你自己拿主意。
- **规范会更新，规则包可能跟不上。** 每个规则包都标了版本。你学校今年发了新规范，而规则包还是旧版的，检查结果可能和新要求对不上。发现了请告诉我们，见[参与贡献](#参与贡献)。
- **段落是程序认的。** 哪段是章标题、哪段是正文、哪段是图题，程序靠样式、大纲级别和文字特征判断。拿不准的段落不修复，但仍可能有认错的时候；看到明显离谱的结果，先确认它把那段认成了什么。
- **WPS 路径没在真机上测过。** 精确检查用 Word 实测过；用 WPS 文字的路径按 Word 的接口写成，还没在装了 WPS 的机器上验证。分页结果按所用程序的排版为准，和打印机或另一个程序的分页可能有出入。

## 参与贡献

发现规则查错了、学校规范更新了、想给自己学校加一个规则包，都欢迎开 Issue。报告误报时请附上规则包名称、那条问题的「应为 / 实际 / 规范」、学校规范的链接和条款号；能附一份删掉个人信息的样例就更好了。提 PR 前请在本地跑通 `cargo test`、`cargo clippy --all-targets` 和 `npm run build`，也请不要提交从学校或期刊下载的模板和规范文件，它们的版权属于发布单位。

## 开发

需要 Node 20+、Rust，以及 [Tauri 2 的系统依赖](https://v2.tauri.app/start/prerequisites/)。

```bash
npm install
npm run tauri dev      # 开发模式运行
npm run tauri build    # 构建安装包
cd src-tauri && cargo test
```

发布由 `.github/workflows/release.yml` 完成：推送 `v*` 标签（版本号与 `src-tauri/tauri.conf.json` 的 `version` 一致）后，在 Windows 上跑测试、构建 `.msi` 和 `-setup.exe`，挂到一个草稿 Release 上。

## 目录结构

- `src/`：React 界面（`App.tsx` 主窗口，`ReportView.tsx` 问题清单，`Preview.tsx` 论文预览，`PackPicker.tsx` 模板库，`SettingsPage.tsx` 设置页）
- `src-tauri/src/engine/`：Rust 检查 / 批注 / 修复引擎（`model.rs` 文档模型，`roles.rs` 段落角色识别，`checks.rs` 检查项，`fix.rs` 格式修复，`edit.rs` 需确认的文字修改，`layout.rs` 精确检查，`extract.rs` 从模板提取规则包，`pack.rs` 规则包格式）
- `src-tauri/src/precise.rs`、`src-tauri/src/collect_layout.ps1`：精确检查时调用 Word / WPS 采集分页结果
- `src-tauri/packs/`：内置规则包，编进程序，文件名即 `meta.id`
- `src-tauri/examples/extract.rs`：规则包开发工具（`draft` / `check` / `test`）
- `src-tauri/examples/survey.rs`：在一批模板上统计段落角色识别情况
- `.github/workflows/release.yml`：发布流程
